= Developing Integrations Using MuleSoft Dev Agent
:page-deployment-options: cloud-ide, desktop-ide

To jumpstart your integration development, use MuleSoft Dev Agent in Anypoint Code Builder. Dev Agent enables you to generate flows or API specifications directly in your project using natural language prompts. These capabilities are powered by large language models (LLMs) that run within the Salesforce Shared Trust Boundary.

NOTE: MuleSoft Dev Agent is available on US, EU, Canada, and Japan cloud hosts.

== Before You Begin

Before you start, ensure that you have the following prerequisites:

* xref:start-acb.adoc[Set up and access the web or desktop IDE].  
* Make sure you have the xref:start-configure-permissions.adoc#permissions[required Anypoint Code Builder permissions].  
* Install Node.js v20. For more information, see https://nodejs.org/en/download[Download Node.js].  
* Log in to Anypoint Code Builder with your Anypoint Platform credentials.  

== Unified Dev Agent Experience

MuleSoft Dev Agent provides a single panel where you can develop integrations and API specifications. Unlike earlier versions of generative features, Dev Agent no longer separates “Flows” and “API Specs” into different modes. Instead, you can type any prompt into the panel, and Dev Agent determines whether to generate a flow, create an API specification, or execute another action such as deploying an application.  

Dev Agent does not insert output through a separate panel. Instead, it writes directly into your project files when you grant edit permissions.  

Depending on your settings, Dev Agent can:  
* Request approval before writing to your files, or  
* Write automatically if *Auto-approve* is enabled in the Dev Agent settings.  

Dev Agent includes the MuleSoft MCP server by default. This server provides out-of-the-box tools, and you can add additional MCP servers from Marketplace or by configuring a remote server.  

You can also extend Dev Agent behavior using *rules* and *workflows*.  
* Rules define how Dev Agent should handle tasks according to your organization’s standards.  
* Workflows define multi-step actions that you can invoke directly from the panel.  

For details on configuring permissions, settings, and MCP servers, see xref:troubleshooting.adoc[Troubleshooting Dev Agent].
