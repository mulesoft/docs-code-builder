== Configure CPU and Memory Resources for an Agent Broker

To configure CPU and memory resources for brokers, deploy the agent network with the Anypoint CLI Agent Fabric plugin. You can't configure broker resources when you deploy from Anypoint Code Builder.

By default, brokers reserve `20m` of CPU and `700Mi` of memory, with limits of `2000m` CPU and `700Mi` memory.

Specify the resource settings in a deployment configuration file or directly in the deploy command. Don't use both methods in the same command.

To specify the settings in a deployment configuration file:

. Create a `deployment-config.yaml` file with the resource settings:
+
[source,yaml]
----
brokers:
  resources.cpu.reserved: 20m
  resources.cpu.limit: 2000m
  resources.memory.reserved: 700Mi
  resources.memory.limit: 700Mi
----
. Pass the file to the deploy command with `--deployment-properties-file`:
+
----
--deployment-properties-file=/path/to/deployment-config.yaml
----

To specify a resource setting directly in the deploy command, use `--deployment-property` with the broker scope, resource property, and value. For example, to reserve `50m` of CPU:

----
--deployment-property brokers:resources:cpu:reserved:50m
----

=== Resource Requirements for Runtime Fabric Targets

Before you deploy an agent network to a Runtime Fabric target, set a resource quota on the namespace that covers every broker gateway and MCP server in the network.

If the namespace quota is too low, the pods can't be scheduled and the deployment fails with error `3018` (`commandTimeout`) instead of an insufficient-resources error. See xref:af-troubleshoot-errors.adoc#cli-error-code-reference[CLI Error Code Reference].

[%header%autowidth.spread,cols="a,a,a,a"]
|===
| Component | Minimum CPU | Minimum Memory | Recommended Limit

| Agent broker ingress gateway, per instance
| `500m`
| `512Mi`
| `2` CPU, `2Gi` memory

| Agent broker egress gateway, per instance
| `500m`
| `512Mi`
| `2` CPU, `2Gi` memory

| MCP server, per server
| `250m`
| `256Mi`
| `1` CPU, `1Gi` memory
|===

For an agent network with one broker and two MCP servers, set a namespace quota of at least `4` CPU and `4Gi` memory.

To check the quota and confirm that the pods are running after you deploy, run:

[source,ssh]
----
kubectl describe resourcequota -n <namespace>
kubectl get pods -n <namespace>
----

On OpenShift, use `oc` instead of `kubectl`.
