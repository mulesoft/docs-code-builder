= Managing Global Configuration Elements

Add, edit, and delete global configurations in Anypoint Code Builder from *Global Elements*. Create connector configurations, TLS contexts, object stores, caching strategies, API Autodiscovery, global error handlers, import project references, and properties files. Manage the same configurations in *Global Elements*, through MuleSoft Vibes, or in the source editor.

== Before You Begin

* xref:start-acb.adoc[Set up and access Anypoint Code Builder].
* xref:int-create-integrations.adoc[Create an integration project].

[[open-global-elements-panel]]
== Open the Global Elements Panel

Open *Global Elements* from *Project Properties* to view and manage the global configurations defined in your project.

. Use one of the these options:
+
* In the canvas toolbar, click *Manage Global Elements* to open *Project Properties* with the *Global Elements* tab already selected.
* In the Explorer, right-click your project and select *Project Properties*, then select *Global Elements* from the menu.
+
*Global Elements* shows a searchable table with the *Type*, *Name*, and *Notes* for each element. 

. In *Selected File*, select a configuration file and view its elements. 
. After you select a file, use *Add New* to create a configuration, or use MuleSoft Vibes. 
+
The table updates in real-time as you make changes.

[[add-global-config]]
== Add a Global Configuration

Add connector configurations and other global configuration types from *Global Elements*.

To add a global configuration:

. Open the <<open-global-elements-panel, Global Elements panel>>.
. Select a configuration file from *Selected File*.
. Click *Add New*.
. In *Select Configuration Type*, search for or browse to the type you want.
+
Types are grouped by category:
+
* *Global Configuration*
* *Connector Configuration*
* *Component Configuration*
* *Caching Strategies*
. Select a type. A form opens, scoped to the file you selected.
. Complete the required fields and save.

The new element appears in the *Configured Elements* table and is written to the selected configuration file.

You can also add global configurations through MuleSoft Vibes using natural language. The element is created with the correct structure and placed in the right file automatically. For example:

* _"Add a Salesforce connector config"_
* _"Register a new properties file"_
* _"Create an HTTP Listener global config on port 8081"_

For more details on using Vibes to manage global elements, see <<vibes-manage-global-configs>>.

[[edit-global-config]]
== Edit a Global Configuration

To edit an existing element, use one of the these methods:

* *Form editor* — Click the *More actions* (*...*) menu next to the element and select *Edit*. A form-driven editor opens with field validation so you can update the configuration. Form editing is available for connector configurations and for these global configuration types:
+
** TLS Context
** Object Store
** Caching Strategy
** API Autodiscovery
** Global Error Handler
** Import Project Reference
** Properties
+
* *Source editor* — Click *More actions* (*...*) > *Go to Source* to jump directly to the element's location in the XML file and edit it in context. Use this option for elements that don't open in the form editor.
* *MuleSoft Vibes* — Describe your change conversationally and Vibes applies it for you.

[[remove-global-config]]
== Remove a Global Configuration

Delete connector configurations and other global configuration elements from *Global Elements*.

To delete a global configuration:

. Open the <<open-global-elements-panel, Global Elements panel>>.
. In the *Configured Elements* table, click the *More actions* (*...*) menu next to the element.
. Select *Delete*.
. Confirm the deletion when the dialog names the element.

The element is removed from the configuration file, and the list refreshes.

You can also remove a global configuration through MuleSoft Vibes. For example:

* _"Remove the Salesforce connector config"_
* _"Delete the HTTP Listener global config"_

Before removing an element, Vibes identifies any flows that reference it and warns you of the impact before making any changes.

[[consolidate-global-configs]]
== Consolidate Global Configurations

If global elements are scattered across multiple configuration files, consolidate them into a single `global-configs.xml` file.

To consolidate from *Global Elements*:

. Open the <<open-global-elements-panel, Global Elements panel>>.
. Click *Consolidate*.

Anypoint Code Builder moves global configuration elements from every file in the project into `global-configs.xml` and updates flow file references.

To consolidate through MuleSoft Vibes, see <<centralize-studio-projects>>.

[[manage-properties-files]]
== Manage Configuration Properties Files

When you create a new project, Anypoint Code Builder automatically generates a `global-configs.xml` file for storing configuration properties separately from flow definitions. If you open a project migrated from Studio, Anypoint Code Builder preserves the existing project structure.

=== Register a Properties File

To register a `.yaml` or `.properties` file as a configuration source, click *Add New* in *Global Elements* and select the configuration properties type. You can also use MuleSoft Vibes. For example:

* _"Register a new properties file"_
* _"Add config.yaml as a configuration properties file"_

Anypoint Code Builder adds a `<configuration-properties>` element to your global config XML and the file appears in *Global Elements*, under *Configuration Properties*.

=== Add Inline Global Properties

To add `<global-property>` key-value pairs, click *Add New* in *Global Elements* and select the global property type. You can also use MuleSoft Vibes. For example:

* _"Add a global property named env with value dev"_

All inline properties are stored in `global-configs.xml` instead of individual application XML files.

[[multi-environment]]
== Set Up Multi-Environment Configuration

Anypoint Code Builder supports the `${env}.yaml` file pattern for environment-specific property files.

If your project contains files such as `dev.yaml`, `qa.yaml`, and `prod.yaml`, they appear in the *Environments* section of *Global Elements*.

To set the default environment, use MuleSoft Vibes. For example:

* _"Set the default environment to dev"_
* _"Set up multi-environment configuration for dev, QA, and prod"_

Vibes adds a corresponding `<global-property>` element to your global configuration file, for example: `<global-property name="env" value="dev"/>`.

Use *Preview Mode* to switch the active environment and verify that property placeholders resolve correctly before you deploy.

[[secure-properties]]
== Work with Secure Properties

Anypoint Code Builder supports the Mule Secure Properties module:

* Generate encrypted property values from Anypoint Code Builder.
* Anypoint Code Builder warns you when a properties file contains unencrypted credentials.

For information about encrypting values and referencing them in your Mule application, see xref:int-create-secure-configs.adoc[]. To edit a secure properties configuration from *Global Elements*, see xref:int-create-secure-configs.adoc#edit-via-ui[].

[[global-element-types]]
== Global Element Types

In addition to connector configurations, you can add, edit, and delete these global configuration types from *Global Elements*:

[%header,cols="20a,60a"]
|===
| Component | What It Does

| *Global Error Handler*
| Set any error handler as the application-wide default. You can also reference handlers from imported projects for consistent exception management across teams.

| *API Autodiscovery*
| Configure your Mule application for API Manager auto-discovery at deployment time. Select from the flows defined in your application when configuring the auto-discovery settings.

| *TLS Context*
| Set up Trust Store and Key Store configurations once, then reference them from any connector that supports TLS.

| *Import Project Reference*
| Import a JAR containing a shared Mule project. Use its flows, error handlers, and connection configurations. Anypoint Code Builder handles POM dependency management. When you import from a library that's added as a project dependency, specify the Mule configuration file to import.

| *Caching Strategy*
| Define a centralized caching strategy that you can reference from Cache scopes across the project.

| *Object Store*
| Create an object store to use with a caching strategy or other components that persist data.

| *Configuration Properties*
| Register a `.yaml` or `.properties` file, or add inline global properties, so your application can resolve placeholders consistently.

|===

For API Autodiscovery configuration details, see xref:int-configure-api-autodiscovery-local.adoc[] and xref:int-autodiscovery-config.adoc[].

[[vibes-manage-global-configs]]
== Use MuleSoft Vibes to Manage Global Configurations

You can use MuleSoft Vibes to create and update global elements by using natural language prompts.

=== Automatic Generation

When Vibes generates a flow that uses a connector, it also generates the corresponding global configuration element. Credentials are stored as property placeholders, and a sample properties file is created for the generated configuration.

=== Natural Language Examples

You can ask Vibes things like:

* _"Create an HTTP Listener global config on port 8081"_
* _"Set up multi-environment configuration for dev, QA, and prod"_
* _"Centralize all global configs into the global-configs.xml file"_
* _"What global elements are defined in this project?"_
* _"Validate my property placeholders"_

[[centralize-studio-projects]]
=== Centralize Configurations from Studio Projects

If your project has global elements scattered across multiple config files (common in projects migrated from Studio), ask Vibes to consolidate them:

_"Move all global configs into global-configs.xml"_

Vibes identifies every global element across your config files, moves them to `global-configs.xml`, and updates all flow file references automatically.

You can also click *Consolidate* in *Global Elements*. See <<consolidate-global-configs>>.

The `manage-global-configurations` skill powers these operations. For more on skills in MuleSoft Vibes, see xref:vibes-skills.adoc[].
