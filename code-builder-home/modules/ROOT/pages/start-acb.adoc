[[login-status-bar]]
=== Sign in to Anypoint Platform from the Status Bar

The status bar shows your login status:

* *Not logged in to Anypoint Platform* indicates that you must sign in to perform tasks that require a connection to Anypoint Platform. 
+
image::acb-not-logged-in.png["Login status message in the status bar"]
+ 
You can sign in by clicking this notification and following the prompts to sign in.
* A link to your user name indicates that you are signed in.
+
You can log out by clicking your user name and following the prompts.

[[login-command]]
=== Sign in to Anypoint Platform from the Command Palette

You can use the Command Palette to sign in to Anypoint Platform.

To sign in from the Command Palette:

// Pointer to Command Palette
include::anypoint-code-builder::partial$acb-reusable-steps.adoc[tags="open-command-palette"]
. Select the following command:
+
[source,command]
----
MuleSoft: Login to Anypoint Platform
----
+
image::anypoint-code-builder::login-to-anypoint-platform.png["Login command within the Command Palette"]
+
[TIP]
--
You can type `login` and use the filter in the results to select the command you want.
--
. Select *Allow* when prompted to sign in to the platform.
+
image::anypoint-code-builder::allow-login-to-anypoint-platform.png[]
+
After logging you in, Anypoint Platform displays a *You can close this page now* message.
+
. To verify your login, ensure that *<your-username>* replaces *Not logged in to Anypoint Platform*. 

[[logout-status-bar]]
=== Log Out from Anypoint Platform from Anypoint Code Builder

Log out by:

. Clicking your username in the status bar 
. Clicking *Yes* when asked *Logout from Anypoint?*

[[change-clouds]]
== Set Anypoint Code Builder to a Different Control Plane

In Anypoint Code Builder, you can change your Anypoint Platform control plane to one of these options:

* US Cloud (default)
* EU Cloud
* Canada Cloud
* Japan Cloud
* India Cloud
* Australia Cloud
* United Kingdom Cloud
* Private Cloud Edition

Anypoint Platform instances do not share user accounts, projects, or other data. For more information, see xref:index.adoc#us-eu-clouds[Cloud Hosts].

Starting with Anypoint Code Builder 1.28.0, you can select *Private Cloud Edition* to connect to a Private Cloud Edition (PCE) 4.3.0 or later control plane that your organization hosts.

To change the control plane:

//shared steps for opening Mule settings
include::anypoint-code-builder::partial$acb-reusable-steps.adoc[tags="open-mule-settings"]
include::anypoint-code-builder::partial$acb-reusable-steps.adoc[tags="mule-settings-nav-options"]
. Scroll to *Mule: Control Plane*.
. Select the desired control plane.
. If you select *Private Cloud Edition*, set *Mule: Control Plane PCE Url* to the URL of your PCE control plane, for example `https://pce.example.com`.
+
Anypoint Code Builder uses this URL only when *Private Cloud Edition* is selected. Anypoint Code Builder imports custom SSL certificates for the PCE host automatically.
. {restart-ide}
. Follow the steps in xref:anypoint-code-builder::start-acb.adoc#login-ide[Sign in to Anypoint Platform from Anypoint Code Builder].
+
If you selected *Private Cloud Edition*, sign in from the Command Palette with this command:
+
[source,command]
----
MuleSoft: Login to Anypoint Platform
----
+
The command opens the PCE sign-in page.

If you selected *Private Cloud Edition*, bundled Mule runtime versions are available, and you can add another Mule runtime version locally. See <<add-local-mule-runtime>>.

[[add-local-mule-runtime]]
== Add a Mule Runtime Version Locally

Starting with Anypoint Code Builder 1.28.0, you can add a Mule runtime version that Anypoint Code Builder does not include. Copy the Mule runtime directory into the `user-installed` folder. Anypoint Code Builder lists that version when you create a project and in *Project Properties*.

Use this option when your environment requires a Mule runtime version that is not bundled with Anypoint Code Builder, such as a version for Private Cloud Edition (PCE) or GIA2H. Bundled Mule runtime versions are also available when the control plane is Private Cloud Edition. See xref:int-versions.adoc#bundled-runtimes[Bundled Mule Runtime Versions].

To add a Mule runtime version:

. Copy the Mule runtime directory into this folder:
+
[source,text]
----
${user.home}/AnypointCodeBuilder/runtimes/user-installed
----
+
Create the `user-installed` folder if it does not exist.
. Create a project, or open *Project Properties*.
+
The Mule runtime version appears in the Mule runtime version menu. See xref:int-versions.adoc#project-version-mule-java[Select Mule and Java Versions for a Project].

[IMPORTANT]
====
Anypoint Code Builder does not validate that a Mule runtime version is compatible with your PCE or GIA2H environment. Confirm compatibility before you run or deploy your application.
====
